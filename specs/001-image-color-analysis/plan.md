# Implementation Plan: Image Color Analysis CLI

**Branch**: `[001-image-color-analysis]` | **Date**: 2026-08-29 | **Spec**: [specs/001-image-color-analysis/spec.md](spec.md)

**Input**: Feature specification from `/specs/001-image-color-analysis/spec.md`

**User directive**: use dotnet core c#

## Summary

Build a cross-platform command-line tool in C# / .NET that accepts a raster image from a file path, the system clipboard, or standard input, identifies the major (dominant) colors, and prints them as named colors with numeric values. Users can choose the color model (RGB, CMYK, etc.), the number of colors to report, and the output format (text, JSON, JSONL, YAML). Optional visual swatch output is rendered when the terminal supports it. Release artifacts are self-contained single-file binaries for Linux, Windows, and macOS published on GitHub Releases with SHA-256 checksums and install scripts.

## Technical Context

**Language/Version**: C# 12 / .NET 8 LTS

**Primary Dependencies**:
- `SixLabors.ImageSharp` — pure managed, cross-platform image loading, decoding, and color quantization.
- `System.CommandLine` — modern official command-line parser.
- `YamlDotNet` — YAML serialization.
- `TextCopy` (optional/placeholder) — evaluated for clipboard text; image clipboard requires platform-specific helpers.

**Storage**: N/A (stateless CLI; no persistent storage).

**Testing**: `dotnet test` with `xUnit` and `Microsoft.NET.Test.Sdk`; integration tests use known sample images.

**Target Platform**: Linux x64, Windows x64, macOS x64 (first-class equal targets); portable self-contained binaries.

**Project Type**: command-line tool / console application.

**Performance Goals**: Analyze a typical 1920x1080 image in under 5 seconds on standard hardware; default quantization uses a fast octree or Wu quantizer with optional downscaling for very large images.

**Constraints**:
- No vendor-specific or native runtime dependencies in the default image path (ImageSharp is fully managed).
- Clipboard image access may require small, isolated platform-specific interop or shell-out to system utilities (`xclip`, `pbpaste`, Windows Clipboard API); this is isolated behind an interface.
- Output coverage percentages must sum to 100% within a 1% tolerance.
- Default color model is RGB; named-color lookup uses a standard CSS/X11 dictionary with nearest-neighbor matching.

**Scale/Scope**: Single-feature CLI; no server, no database, no multi-user state. Release pipeline builds three platform binaries plus checksums, install scripts, and the MIT License file.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

### Principle I — Cross-Platform Compatibility
- **Status**: PASS
- **Evidence**: .NET 8 produces self-contained single-file executables for Linux, Windows, and macOS. ImageSharp is fully managed with no native dependencies. Clipboard image path is abstracted behind an interface with per-platform implementations.

### Principle II — Simplicity
- **Status**: PASS (with note)
- **Evidence**: One console project, one test project, minimal abstractions. The only complexity is the isolated clipboard adapter, which is required by the feature and hidden behind a simple interface.

### Principle III — Complete Documentation
- **Status**: PASS
- **Evidence**: README, usage examples, inline XML documentation, and the `contracts/` and `quickstart.md` artifacts produced by this plan cover public options and exit codes.

### Principle IV — Memory Safety and Exploit Resistance
- **Status**: PASS
- **Evidence**: C# / .NET is memory-safe. ImageSharp validates image bounds. Input streams are length-limited; max image dimensions and file size are capped before decoding.

### Principle V — CLI-First Design
- **Status**: PASS
- **Evidence**: All functionality is exposed via command-line options; input is accepted from file, stdin, or clipboard; output goes to stdout; errors to stderr; machine-readable JSON/JSONL/YAML formats are supported.

### Post-Design Re-check
- **Status**: PASS
- **Evidence**: Phase 1 contracts (`cli-commands.md`, `output-formats.md`) and `data-model.md` confirm all I/O is CLI-driven, options are explicit, and exit codes are documented. The data model has no persistent state and no hidden side effects.

**Structure Decision**: Single console project (`src/GetMajorColors`) plus one xUnit test project (`tests/GetMajorColors.Tests`). All platform-specific clipboard logic is isolated in `src/GetMajorColors/Clipboard`. Output formatters are separated so new formats can be added without touching command handlers. A top-level `LICENSE` file will contain the MIT License text; third-party notices for ImageSharp, System.CommandLine, and YamlDotNet will be collected at build time and shipped with release archives.
